# 🌍 Global Seismic Trends: Data-Driven Earthquake Insights

A comprehensive data analytics pipeline that retrieves, processes, and analyzes global earthquake data from the USGS (United States Geological Survey) Earthquake Hazards Program API. The project covers the full data lifecycle — from API-based data collection to SQL-driven analytics and an interactive Streamlit dashboard.

## Problem Statement

Analyze and interpret global earthquake data to identify seismic patterns, trends, and risk zones. Build a data-driven system using API-based retrieval, preprocessing, and SQL analytics for meaningful earthquake insights.

## Business Use Cases

- **Government Agencies:** Assess earthquake risks and plan disaster management strategies
- **Insurance Companies:** Evaluate seismic risk zones for policy pricing
- **Researchers:** Study seismic patterns, depth trends, and magnitude distributions
- **Urban Planners:** Support infrastructure resilience and emergency response planning

## Setup & Installation

### Prerequisites
- Python 3.10 or higher (developed on Python 3.13)
- MySQL Server **8.0+** (the window function `LAG()` is used in Q23)
- pip (Python package manager)

### Step 1: Create a Virtual Environment & Install Dependencies
```bash
python -m venv .venv
.venv\Scripts\activate          # Windows  (macOS/Linux: source .venv/bin/activate)
pip install -r requirements.txt
```

### Step 2: Verify MySQL is Running & Set Your Credentials (`.env` file)
Make sure your MySQL server is running. Database credentials are read from **environment variables** (never hard-coded), loaded from a local `.env` file with `python-dotenv`:

```bash
copy .env.example .env      # Windows  (macOS/Linux: cp .env.example .env)
```
Then open `.env` and set your own MySQL password:
```
DB_USER=root
DB_PASSWORD=your_mysql_password_here
DB_HOST=localhost
DB_PORT=3306
DB_NAME=earthquake_db
```
> `.env` is listed in `.gitignore`, so your password is never pushed to GitHub. Only the template `.env.example` is committed.

### Single Command Alternative
```bash
python run_pipeline.py                # Steps 1 → 2 → 3 → 5
python run_pipeline.py --skip-scrape  # Reuse existing data/earthquakes_intermediate.csv
```

## How to Run

Execute the scripts **in order** from the project folder — each step depends on the previous one:

### Step 1: Collect Data from USGS API
```bash
python src/01_data_collection.py
```
- Fetches M3.0+ earthquakes for the last 5 complete calendar years, month by month (60 months × 2 formats = 120 API calls)
- Merges CSV and GeoJSON formats on the event `id`
- Saves to `data/earthquakes_intermediate.csv` (the old file is removed at the start of each run)
- ⏱️ Takes several minutes, depending on your internet connection

### Step 2: Clean and Preprocess
```bash
python src/02_data_cleaning.py
```
- Converts timestamps, extracts and normalises `country`, fixes data types, fills missing values, removes duplicates
- Adds derived columns (Year, Month, Day, Hour, Day_of_week, depth_flag, severity_flag)
- Saves to `data/earthquakes_cleaned.csv`

### Step 3: Load into MySQL
```bash
python src/03_load_to_mysql.py
```
- Creates `earthquake_db` using a `pymysql` cursor
- Loads the cleaned data into the `earthquakes` table with SQLAlchemy `df.to_sql(if_exists="replace", chunksize=10000)`
- Verifies the row count with `SELECT COUNT(*)`

### Step 4: Run SQL Queries
Open `sql/04_sql_queries.sql` in MySQL Workbench (or any SQL client) and run the queries one by one.

### Step 5: Exploratory Data Analysis
```bash
python src/05_eda.py
```
- Prints summary statistics, right-skewness checks (`mean > median`), Pearson correlations (`df.corr()`), and 3 hypothesis tests (`ttest_ind`, `f_oneway`, `chi2_contingency`)
- Saves 7 charts to `docs/figures/`

### Step 6: Launch Dashboard
```bash
streamlit run app.py
```
- Automatically connects to MySQL (`earthquake_db.earthquakes`) using the credentials in `.env`
- Use the year / magnitude filters in the sidebar — every query and chart updates live

### Data Collection Strategy

**Why month-by-month API calls?**
The USGS API has a limit of approximately 20,000 records per request. With a 3.0+ magnitude filter over 5 years, we can expect ~50,000–100,000 events. Fetching month-by-month ensures each request stays within the API's limits.

**Why both CSV and GeoJSON formats?**
- **CSV** provides the core 22 columns (time, mag, place, depth, etc.)
- **GeoJSON** provides additional fields not in CSV: `tsunami`, `sig`, `types`, `ids`, `sources`, `alert`
- Merging both gives us the complete 26-feature dataset required by the project

### Data Cleaning Decisions

| Decision | Choice | Why | Alternatives Considered |
|----------|--------|-----|------------------------|
| CSV + GeoJSON merge | `pd.merge` on `id` | Row order between two API calls is not guaranteed; a position-based copy can silently attach the wrong `sig`/`tsunami` to an event | Direct column assignment by position |
| Missing numeric values | Median | Robust to outliers (e.g., nst ranges 1–500+) | Mean (pulled by extremes), 0 (misleading), dropping rows (loses 30–50% of data) |
| Missing `alert` values | `'unassessed'` | Semantically correct — "not evaluated" ≠ "safe" | `'green'` (implies evaluation), `'none'` (ambiguous) |
| Missing text labels | `'unknown'` before `astype(str)` | Otherwise NaN becomes the text `"nan"` and appears as a fake category in GROUP BY | Leave as NaN (becomes NULL / "nan") |
| Timestamps | Parse as UTC, drop tz label | MySQL `DATETIME` has no timezone; UTC is the seismology standard | Convert to local IST time (confusing for global data) |
| Country extraction | Custom `def get_country(place):` with `.apply()` and `.split(",")` | Place format is `"distance direction of City, Region"` | Reverse geocoding API (extra API, slow, not required) |
| Country normalisation | `.replace()` dictionary mapping (`CA` → `California`, `MX` → `Mexico`) | Standardizes state/country abbreviations using `.replace()` | No normalisation (splits same region into multiple groups) |
| US events | Kept at state level | Alaska, California, Hawaii are different tectonic settings; USGS itself writes them as states | Roll up to "United States" |
| Duplicate removal | By `id` column | USGS event IDs are unique identifiers | By (time, lat, lon, mag) — could remove real aftershocks |
| Depth flag | Binary (shallow/deep) | Project says "flag" = binary indicator | 3-level (shallow/intermediate/deep) |
| Severity flag | Binary (standard/destructive) | Project says "flag" = binary indicator | 4-level (minor/moderate/major/destructive) |
| Depth threshold | 70 km | Standard seismological boundary (USGS/NEIC) | 50 km (too strict), 100 km (too lenient) |
| Severity threshold | 6.0 magnitude | USGS standard for "potentially destructive" | 5.0 (too many events), 7.0 (too few) |

### Database Design Decisions

| Decision | Choice | Why |
|----------|--------|-----|
| Table name | `earthquakes` | Clear, descriptive table name for seismic events |
| Database creation | `pymysql` cursor → `CREATE DATABASE IF NOT EXISTS earthquake_db` | Standard connect → cursor → execute → commit workflow |
| Table creation & insert | `df.to_sql("earthquakes", if_exists="replace", index=False, chunksize=10000)` | `replace` makes re-runs safe (no duplicate rows); `chunksize` keeps each batch below MySQL `max_allowed_packet` |
| Datetime columns | `pd.to_datetime()` before `to_sql` | `time` / `updated` are stored as MySQL `DATETIME`, so `YEAR()`, `MONTH()` and ordering work correctly |
| Credentials | Environment variables (`DB_USER`, `DB_PASSWORD`, …) loaded from `.env` via `python-dotenv` | Password stays out of the source code and GitHub; each user keeps their own `.env` (template: `.env.example`) |

## Analytical Queries

The project implements **26 out of 30** SQL queries across 6 thematic sections:

| Section | Queries | Focus |
|---------|---------|-------|
| Magnitude & Depth | Q1, Q2, Q3, Q5 | Strongest/deepest events, magnitude types |
| Time Analysis | Q6, Q7, Q8, Q9, Q10 | Temporal patterns, networks |
| Impact & Alerts | Q11, Q13 | Significance-based impact, alert levels |
| Event Type & Quality | Q14, Q15, Q16, Q18, Q19, Q20 | Status, types, stations, tsunamis |
| Seismic Patterns | Q21, Q22, Q23, Q24 | Country-level patterns, growth rates |
| Depth & Location | Q25, Q26, Q27, Q28, Q30 | Equatorial depth, ratios, reliability |

### Note on Q11 and Q13 (Impact Proxy)
USGS earthquake data does **not** include direct casualty counts or economic loss figures. The `sig` (significance) column is used as a proxy — it is a composite score (0–1000+) calculated by USGS based on magnitude, felt reports, and estimated impact, making it the closest available measure.

## Skipped Queries & Justification

| Query | Question | Reason for Skipping |
|-------|----------|---------------------|
| **Q4** | Average depth per continent | `continent` is not part of the 26 features defined in the project specification. The USGS API does not provide continent data, and mapping countries to continents would require an external dataset not specified in the project. |
| **Q12** | Total estimated economic loss per continent | Requires both an `economic_loss` column (not provided by USGS) and a `continent` column (not in the 26 features). |
| **Q17** | Average RMS and gap per continent | Same as Q4 — requires `continent` column not available in the dataset. |
| **Q29** | Consecutive earthquakes within 50 km and 1 hour | Requires Haversine distance calculation between consecutive events — a complex spatial computation that goes beyond standard SQL analytics and is better suited for specialized geospatial tools. |

> These omissions are **deliberate and documented** — not oversights. The data preparation section of the project specification defines exactly 26 features and derived columns (Year, Month, Day, Day_of_week, depth_flag, severity_flag). Continent mapping and economic loss data are not part of this specification.

## Key Findings & Insights (Verified on 104,464 USGS Records, 2021–2025)

1. **Dataset Scale & Magnitude Distribution:** Across `2021-01-01` to `2025-12-31`, **104,464 M3.0+ seismic events** were recorded across **493 regions** (mean `mag = 4.26`, median `4.30`). Only **675 events (`0.65%`)** reached the destructive threshold (`M ≥ 6.0`), led by the **M8.8 Kamchatka Peninsula, Russia Earthquake (`2025-07-29`, depth `35 km`)** and the **M8.2 Chignik, Alaska Earthquake (`2021-07-29`, depth `35 km`)** (Q1, Q3).
2. **Depth Regimes & Tectonic Settings:** **78,018 events (`74.68%`)** are shallow (`≤ 70 km`) and **26,446 (`25.32%`)** are deep (`> 70 km`). Continental collision zones exhibit extreme shallow-to-deep ratios — **Iran (`292.33:1`)**, **Canada (`271.00:1`)**, and **Nepal (`74.00:1`)** (Q26) — whereas deep-focus earthquakes (`> 300 km`, max **`681.24 km` in Vanuatu**, Q2) concentrate in oceanic subduction trenches led by **Fiji (`2,289` events, avg depth `560.63 km`)**, **South of Fiji (`1,529`)**, **Tonga (`555`)**, and **Japan (`344`)** (Q30).
3. **Most Seismically Active & Impacted Regions:** Combining frequency and magnitude (`count × avg_mag`, Q24), the top 3 active regions are **Alaska (`43,077.01` — `12,425` events)**, **Indonesia (`35,237.30` — `7,840` events)**, and **Japan (`28,309.80` — `6,292` events)**. By cumulative significance (`sig`, Q11), **Indonesia (`2,456,398`)**, **Alaska (`2,368,680`)**, **Japan (`1,980,912`)**, **Russia (`1,779,904`)**, and the **Philippines (`1,404,859`)** experience the highest total impact.
4. **Temporal Patterns & Aftershock Swarms:** Annual totals ranged between `18,659` (`2024`) and **`22,841` (`2025`, `+22.41%` YoY)** (Q6, Q23), with the 2025 surge and the **August monthly peak (`9,857` events, Q7)** driven by the July–August 2025 Kamchatka M8.8 aftershock sequence. Weekday (`14,857–15,105` events/day, Q8) and hourly (`4,318–4,683` events/hour, Q9) distributions are flat, confirming tectonic time-invariance.
5. **Network Coverage & Data Reliability:** The **`us` network reports `87.69%` (`91,603`)** of global events, followed by `pr` (`5,597`) and `ak` (`3,145`) (Q10), and **`99.86%` (`104,315`)** of records are human-reviewed (Q14). Events with high station coverage (`nst > 50`, Q18) average **`M4.64`** vs **`M4.16`** for lower coverage, while the highest location uncertainty (`gap` + `rms`, Q28) occurs along remote island arcs (Aleutian Islands and Tonga).
6. **PAGER Alerts & Hypothesis Testing (`scipy.stats`):** PAGER alert tiers scale sharply in both magnitude and significance: **`red` (`24` events, avg `M6.69`, avg `sig = 2,313.38`)**, **`orange` (`22`, avg `M6.30`, `sig = 1,195.95`)**, **`yellow` (`124`, avg `M6.02`, `sig = 801.14`)**, and **`green` (`4,085`, avg `M5.38`, `sig = 480.54`)** (Q13, Q20). Across **625 tsunami-flagged events** (`114–142`/year, Q19), mean magnitude is **`5.42` vs `4.25`** for non-tsunami events (**`+1.16` gap**, Q27). All three statistical hypothesis tests reject the null hypothesis (`p_val < 0.05`):
   - **T-Test (`ttest_ind`):** Tsunami vs Non-Tsunami magnitude (`p_val = 0.0 < 0.05` → `True`)
   - **ANOVA (`f_oneway`):** Magnitude across Alert Levels (`green`, `yellow`, `orange`, `red`) (`p_val = 3.51 × 10⁻⁴⁶ < 0.05` → `True`)
   - **Chi-Square (`chi2_contingency`):** `pd.crosstab(df["alert"], df["severity_flag"])` (`p_val = 0.0 < 0.05` → `True`)

### Business Recommendations
- **Governments / urban planners:** prioritise building-code enforcement in regions with frequent *shallow* M6+ events (Q3, Q26).
- **Insurers:** use the composite activity score (Q24) and significance totals (Q11) to rank regional risk.
- **Coastal authorities:** tsunami warning investment should target subduction-zone coasts where large shallow events occur (Q19, Q27).
- **Monitoring agencies:** add stations where Q28 shows poor coverage (high azimuthal gap).
